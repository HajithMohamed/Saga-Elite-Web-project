0.4  NESTED SCROLL CONTAINERS ON PRODUCT/DROPS  (the scrolling bug)
--------------------------------------------------------------------------------

  When you open Product or Drops, the page wraps the content in FOUR
  competing height / overflow contexts:

   (1)  Layout <main>           overflow-y-auto pb-16 lg:pb-0
        FILES: Client-Side/src/components/admin-components/Layout.jsx:28

   (2)  .admin-page-shell        min-h-screen w-full bg-[#050505] p-4 md:p-6
        FILES: Client-Side/src/index.css:112-114

   (3)  Page motion.div          overflow-hidden min-h-[calc(100vh-80px)]
        FILES: Client-Side/src/pages/admin-view/Product.jsx:1317
               Client-Side/src/pages/admin-view/Drops.jsx:697

   (4)  Inner <main>             flex-1 overflow-y-auto px-8 md:px-16 py-12
        FILES: Client-Side/src/pages/admin-view/Product.jsx:1347
               Client-Side/src/pages/admin-view/Drops.jsx:718

  Symptoms this produces:
   - The inner page scrolls instead of the layout, so the top Header can
     visually de-anchor on certain viewport heights.
   - Sticky FormTabs (top-[88px]) clip into the inner header when a form
     is opened.
   - On mobile, the bottom nav (pb-16 in Layout) sometimes overlaps the
     last ~64px of the inner scroll area.
   - Two competing scroll-y contexts can briefly show double scrollbars
     on Windows Chromium.

        - Product.jsx  lines 1323-1345
        - Drops.jsx    lines 703-716
   2. Remove the duplicate big title block (eyebrow + h2 + paragraph):
        - Product.jsx  lines 1352-1359 ("INVENTORY REGISTRY" + "Product Ledger")
        - Drops.jsx    lines 720-735   ("RELEASE REGISTRY"   + "Drop Ledger")
      Let <AdminPage> own the title. AdminPage already takes eyebrow,
      title, description as props — those values are already passed in

FIX 1.3  Scrolling issues on Product & Drops
--------------------------------------------------------------------------------

  CURRENT
   - 4 nested height / overflow contexts (mapped in PHASE 0.4 above).
   - Scroll happens INSIDE the page, not at the layout level.

  PROBLEM
   - Top Header can de-anchor on certain viewport heights.
   - Sticky FormTabs (top-[88px]) clip into the inner header.
   - Mobile bottom nav can overlap the inner scroll area.

  FIX (design-only, no behavior change)
   1. In Product.jsx line 1317 and Drops.jsx line 697, change:
        className="flex-1 flex flex-col overflow-hidden bg-surface
                   min-h-[calc(100vh-80px)] text-on-surface rounded-3xl
                   border border-white/10"
      to:
        className="flex-1 flex flex-col bg-surface text-on-surface
                   rounded-3xl border border-white/10"
      Removes the overflow-hidden + min-h-[calc(100vh-80px)] that
      forces an inner viewport. Let <AdminPage> + Layout own height.

   2. Replace the inner <main className="flex-1 overflow-y-auto ..."> at
      Product.jsx:1347 and Drops.jsx:718 with a plain <div className="
      px-8 md:px-16 py-12 scroll-smooth">. Drop the overflow-y-auto on
      this element. Scrolling will then happen ONLY at Layout.jsx:28,
      which is the correct scroll root.

   3. In AdminFormShell (used by Product/Drops when editing/creating),
      the sticky tab strip uses top-[88px]. Once step 1 is done, change
      it to top-20 so it pins flush against the 80px Header.
        FILES: Client-Side/src/components/admin-components/_form/FormTabs.jsx
               (also AdminFormShell.jsx if it sets its own sticky offset)
