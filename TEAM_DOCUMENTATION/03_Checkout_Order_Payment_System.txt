PERSON 3 DOCUMENTATION
Role: Checkout, Order, Payment and Notification System Developer


1. Role Summary
---------------
This role owns the customer purchase journey after product selection. It covers
cart-to-checkout flow, order creation, stock deduction during checkout, payment
reference generation, manual bank payment proof upload, sample card payment,
admin payment verification, order status management, refunds, invoices,
customer notifications, admin payment alerts and real-time order/payment
updates.

This role connects the customer side and operations side. It makes sure that
orders are created correctly, payments are verified, customers are notified and
admins can manage order fulfillment.

4. Database and Model Responsibilities
--------------------------------------
Primary models:

- Order
  Stores order data. Important fields:
  user, guest, guestEmail, slug, items, totalAmount, shippingAddress,
  contactNumber, paymentMethod, paymentProofUrl, transactionId,
  paymentProofHash, paymentVerifiedAt, referenceNumber, status,
  cancellationReason, cancelledAt, cancelledBy, refundAmount, refundReason,
  refundNote, refundedAt, refundedBy, paymentStatus, gift, notes, couponCode,
  couponDiscount and expiresAt.

  Order item fields:
  product, productName, productArtNo, productSlug, variantSku, size, color,
  quantity, unitPrice and totalPrice.

  Important statuses:
  pending, pending_payment, verification_pending, confirmed, shipped,
  delivered, cancelled, refund_requested and refunded.

- ManualPayment
  Stores payment references and verification records. Important fields:
  referenceNumber, slug, orderId, userId, guestId, amount, currency,
  paymentType, cardDetails, proofUrl, proofSubmittedAt, status, generatedAt,
  expiresAt, verifiedAt, verifiedBy, rejectionReason, adminNotes,
  extensionGranted, OCR audit data and bankVerification data.

  Important statuses:
  pending_payment, proof_submitted, pending_bank_confirmation, verified,
  rejected and expired.

- Notification
  Stores user notifications for drop, offer, order, admin, reminder and system
  messages.

- ShippingZone
  Stores Sri Lankan delivery zones, provinces, fees, estimated days and active
  state.

- Coupon
  Stores discount rules used at checkout.

- UserCoupon
  Stores user reward coupons.

- Product
  Stock is deducted/restored from Product variants during order operations.

- Gift
  Gift is selected and attached to Order.

- Guest and User
  Orders can belong to registered users or guests.

- OrphanBankCredit
  Stores unmatched bank credits detected by bank integration.

6. Main Business Logic
----------------------
Order creation logic:

1. Customer submits checkout form with items, address, contact, payment method,
   coupon and optional guest email.
2. validateOrderCreate sanitizes order input.
3. order-controller uses a transaction.
4. Each product and selected variant is loaded.
5. Variant stock is checked.
6. Product quantity limits and previous purchases are checked.
7. Variant stock is deducted.
8. Coupon is evaluated and discount is applied if valid.
9. Gift eligibility is calculated and gift is attached.
10. Order is created with payment status and order status.
11. Manual payment record may be created if payment method is bank transfer.
12. Email, WhatsApp, notification and socket events are sent.

Manual payment logic:

1. Customer creates an order with manual bank transfer.
2. Backend generates a unique ManualPayment reference and slug.
3. Customer sees bank details and reference number.
4. Customer uploads proof image/PDF or submits proof URL.
5. OCR extracts reference/amount where possible.
6. Payment moves into proof_submitted or pending_bank_confirmation.
7. Admin reviews in PendingPaymentsPage or PaymentVerificationPage.
8. Admin approves or rejects.
9. Approval updates ManualPayment, Order status and paymentStatus.
10. Rejection updates payment/order status and sends customer notification.

Bank auto-verification logic:

1. bank-email-watcher polls configured bank inbox.
2. Bank parser extracts amount, reference and transaction data.
3. Matching ManualPayment is found.
4. bankVerification is updated.
5. Payment can move to verified if data matches.
6. Customer/admin receive notifications.

Order status logic:

1. Admin updates order status.
2. Controller checks allowed transitions.
3. Cancellation restores product stock.
4. Delivered status updates user stats and membership tier.
5. Delivered status can send review request.
6. Socket events refresh customer and admin order views.

Refund logic:

1. Admin opens refund modal.
2. Admin enters amount, reason and note.
3. Backend validates refund conditions.
4. Order is marked refunded/refund data recorded.
5. Customer is notified.

Invoice logic:

1. Admin/customer requests invoice.
2. getOrderInvoice loads order and bank/site config.
3. invoice-pdf streams PDF response.


7. Admin Panel Flow
-------------------
Admin order flow:

1. Admin opens /admin/order.
2. PermissionGuard checks orders permission.
3. Backend checks authMiddleware and requirePermission("orders").
4. Admin sees all orders and order details.
5. Admin changes order status or performs bulk status update.
6. Backend validates transition.
7. Customer gets web/email/WhatsApp notification where applicable.
8. Socket event refreshes order dashboards.

Admin payment verification flow:

1. Admin opens /admin/payments/pending or /admin/manual-payments.
2. PermissionGuard checks verifyPayments permission.
3. Admin sees queue of pending/proof-submitted payments.
4. Admin opens payment detail.
5. Admin reviews proof image, OCR data, order amount and bank status.
6. Admin approves or rejects with notes.
7. Backend updates ManualPayment and Order.
8. Customer receives decision notification.
9. Admin log records the verification action.

Admin shipping flow:

1. Admin opens /admin/shipping.
2. PermissionGuard checks manageInventory permission.
3. Admin creates/edits province zones, delivery fee and free-above threshold.
4. Checkout can use shipping zone data for delivery calculation/display.


8. Shopping Flow
----------------
Customer checkout flow:

1. Customer browses products or drops.
2. Customer adds selected variant to cart.
3. Cart displays quantity and remaining stock.
4. Customer opens checkout.
5. Customer enters shipping address and contact number.
6. Customer applies coupon if available.
7. Customer chooses payment method.
8. Backend creates order and deducts stock.
9. Customer is sent to success/payment page.

Manual payment customer flow:

1. Customer chooses manual bank transfer.
2. Order is created as pending_payment.
3. Manual payment reference is generated.
4. Customer transfers money using shown bank details.
5. Customer uploads receipt/proof.
6. Customer can check status or request extension.
7. After admin/bank approval, order becomes confirmed.

Card/sample payment customer flow:

1. Customer chooses card payment.
2. CardPaymentPage collects cardholder data.
3. Backend validates card number using Luhn check.
4. Payment record is created/verified through sample flow.
5. Order status updates.

Order tracking flow:

1. Customer opens order tracking.
2. Page fetches order status.
3. Socket events order:refresh and order:refresh:public update the page.
4. Customer sees status changes without manual refresh.
