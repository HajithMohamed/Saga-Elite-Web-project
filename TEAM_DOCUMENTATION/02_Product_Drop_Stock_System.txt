PERSON 2 DOCUMENTATION
Role: Product, Drop and Real-Time Stock System Developer


1. Role Summary
---------------
This role owns the product catalog, limited-edition drop system, category
structure, product listing experience, product detail experience, admin product
management, admin drop management, variant stock system, low-stock alerts and
real-time product/drop updates.

This is the core selling system. It controls what products exist, how they are
grouped into drops/categories, how customers discover them and how stock stays
accurate across shopping and admin views.

4. Database and Model Responsibilities
--------------------------------------
Primary models:

- Product
  Main catalog model. Important fields:
  name, slug, artNo, description, story, fabric, gsm, fitType,
  careInstructions, sizeGuide, brand, category, subCategory, categoryPath,
  categoryId, tags, relatedProductIds, trendScore, isDeal, dealEndsAt, drop,
  basePrice, originalPrice, salePrice, discountPercent, costPrice, lastSoldAt,
  variants, totalStock, soldCount, wishCount, viewCount, cartAddCount,
  averageRating, reviewCount, isLimited, maxPerUser, isFeatured, isActive and
  lowStockThreshold.

  Variant fields:
  sku, size, color, colorCode, stock and priceAdjustment.

  Important model logic:
  - Auto-generates slug from name and art number.
  - Assigns variant SKUs.
  - Recalculates totalStock from variants.
  - Has virtual images relation.
  - Has text index for product search.

- Drop
  Stores drop name, slug, description, headline, manifesto, cinematicMode,
  vipEarlyAccessHours, releaseDate, endDate, isPublished and isArchived.
  Has virtual images and products.

- Category
  Stores category names, slugs, parent/child hierarchy and menu/category data.

- Image
  Stores product/drop/system image metadata and display order.

- SmartAlert
  Stores low-stock and operational alerts with kind, severity, title, message,
  dataSnapshot, acknowledged state and expiry.

- Offer and Deal
  Used for product promotions, aging stock and homepage/catalog offer display.

- UserActivityLog
  Tracks product-related user behavior such as dwell/view/action events.

- Review
  Product rating fields update Product averageRating and reviewCount.

6. Main Business Logic
----------------------
Product creation/update logic:

1. Admin enters product details and variants in Product.jsx.
2. Frontend validates minimum form requirements.
3. Product slice sends create/update request.
4. Backend validates product payload.
5. Product model normalizes art number and assigns variant SKUs.
6. Product model creates slug and calculates totalStock.
7. Controller saves product and emits product socket events.
8. Product list/detail pages refresh or patch live product state.

Variant/stock logic:

1. Each product has variants with size, color, colorCode, SKU and stock.
2. totalStock is calculated from all variant stock values.
3. Product card and detail page show sold-out or low-stock messages.
4. Cart and order logic validate selected variant stock before purchase.
5. Order creation deducts stock from the selected variant.
6. Cancelled orders can restore stock through order logic.
7. Smart alerts detect products below low-stock thresholds.

Drop logic:

1. Admin creates a drop with releaseDate, optional endDate, published state and
   optional VIP early access.
2. Products can be attached to a drop.
3. Public drop pages show live/upcoming/closed state based on dates.
4. Drop pages display related products and remaining stock.
5. Drops can be archived instead of deleted.
6. Drop deletion checks linked products and images.

Filtering/search logic:

1. ProductListing stores filters in URL query params.
2. Frontend sends query params to backend.
3. pagination-middleware builds MongoDB aggregation filters.
4. Product results include images and drop data through lookup.
5. Listing UI updates without losing shareable URL state.

Real-time logic:

1. Backend emits product:created, product:updated, product:deleted and
   drop:created/drop:updated events.
2. Frontend SocketBridge and hooks receive events.
3. Product detail/list/drop pages refetch or patch relevant data.
4. Admin sidebar/dashboard badges can update from alert events.


7. Admin Panel Flow
-------------------
Product admin flow:

1. Admin opens /admin/product.
2. PermissionGuard checks products permission.
3. Product page loads products, drops and categories.
4. Admin creates or edits product.
5. Admin configures variants, stock, price, cost, category and drop.
6. Admin uploads images to Cloudinary through image APIs.
7. Backend validates, saves and logs action.
8. Product socket event refreshes customer/admin views.

Drop admin flow:

1. Admin opens /admin/drop.
2. PermissionGuard checks drops permission.
3. Admin creates scheduled drop with dates and content.
4. Admin uploads/reorders drop images.
5. Products can be linked to the drop from Product admin.
6. Admin can archive old drops.
7. Public drop index/detail reflects the new state.

Stock alert admin flow:

1. Product stock drops through sales or manual edits.
2. Smart alert job checks threshold.
3. Alert appears in admin smart alerts/sidebar.
4. Admin can open Products with low-stock filter.
5. Admin can update stock, deactivate product or create offer.


8. Shopping Flow
----------------
Catalog shopping flow:

1. Customer opens /shopping/product-list.
2. ProductListing loads products with filters.
3. Customer filters by category, stock, size, color, price, sort or limited.
4. Customer opens product detail page.
5. ProductDetails loads selected product and related rails.
6. Customer selects size/color variant.
7. UI displays selected stock and low-stock warning.
8. Customer adds item to cart or wishlist.
9. Cart/checkout validates current stock before order creation.

Drop shopping flow:

1. Customer opens /shopping/drops.
2. DropsIndex lists live/upcoming/archive drops.
3. Customer opens /shopping/drop/:slug.
4. DropDetails shows live state, hero, timeline, stock availability and
   products.
5. Customer selects product from drop and continues shopping.
