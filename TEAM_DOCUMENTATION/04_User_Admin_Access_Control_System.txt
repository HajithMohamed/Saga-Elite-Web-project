PERSON 4 DOCUMENTATION
Role: User Authentication, Admin Panel and Access Control Developer


1. Role Summary
---------------
This role owns user accounts, authentication, guest accounts, customer profile,
cart/wishlist APIs, admin panel shell, role-based access control, super admin
management, customer management, admin global search, admin notifications,
reviews, recommendations, smart alerts and analytics dashboard access.

This role is responsible for who can enter the system, what they can access and
how admins manage users and operations safely.

  Stores guest checkout/customer data. Important fields:

  Stores user login attempts/activity.

  Stores review insight summaries and recommendations.

- Recommendation
  Stores AI-generated recommendations by type such as reviews, products, drops,
  analytics, improvements and ideas.

- SmartAlert
  Stores operational/admin alerts.

- UserCoupon
  Stores user reward coupons for rewards page and loyalty features.

6. Main Business Logic
----------------------
Authentication logic:

1. Customer registers with email, password and phone.
2. Request validation checks email/password strength.
3. Password is hashed by User model pre-save hook.
4. OTP is generated and emailed.
5. Customer verifies OTP.
6. Login checks password and active status.
7. JWT is issued and saved to cookie/local token.
8. checkAuth loads current user on app start.

OAuth logic:

1. Customer clicks Google or Facebook login.
2. Frontend sends provider access token.
3. Backend verifies/fetches provider profile.
4. Existing user is matched by provider ID/email.
5. New user is created if needed.
6. JWT is issued.

RBAC logic:

1. User role is stored in User.role.
2. Sub-admin role is stored in User.subRole.
3. Permission flags are stored in User.permissions.
4. Frontend PermissionGuard blocks pages without permission.
5. Backend requirePermission blocks API access without permission.
6. Super admins bypass permission checks.

Super admin logic:

1. Super admin creates admin/sub-admin.
2. Temporary password can be generated and emailed.
3. Sub-role presets fill default permissions.
4. Super admin can update role, permissions, active state and password.
5. AdminLog stores audit records.

Customer management logic:

1. Admin opens Users page.
2. Backend returns users with order/customer data.
3. Admin filters by membership, provider, status or tags.
4. Admin can activate/deactivate, set membership, reset password, delete user
   or bulk tag users.

Review moderation logic:

1. Customer creates review after purchase.
2. Review can be classified and rating updates product metrics.
3. Admin reviews can be categorized, replied to, featured, flagged or bulk
   moderated.
4. Socket event review:refresh updates admin/customer review pages.

Recommendation/alert logic:

1. Jobs generate recommendations and smart alerts.
2. Admin views Recommendations and Alerts pages.
3. Admin can regenerate recommendations or acknowledge alerts.
4. Admin sidebar and dashboard can update counts through sockets.


7. Admin Panel Flow
-------------------
Admin login and route access:

1. Admin logs in through auth drawer/form.
2. App.jsx dispatches checkAuthAction.
3. If role is admin/super_admin/superadmin/sub_admin, default route becomes
   /admin/dashboard.
4. AdminLayout renders sidebar, header, global search and notification dropdown.
5. PermissionGuard checks page-level permissions.
6. Backend middleware checks the same permission for API calls.

Super admin flow:

1. Super admin opens /admin/super-admin.
2. Frontend checks superAdminOnly.
3. Backend checks requireSuperAdmin.
4. Super admin creates/updates/deactivates admins.
5. System sends welcome/password email if needed.
6. AdminLog stores actions.

Global search flow:

1. Admin types at least two characters in GlobalSearchDropdown.
2. Frontend dispatches runAdminSearch.
3. Backend globalSearch searches products, orders, customers, drops and coupons.
4. Results are grouped and displayed in dropdown.

Review/admin insight flow:

1. Admin opens Reviews, Recommendations, Alerts or Analytics.
2. PermissionGuard checks manageReviews or viewAnalytics.
3. Backend aggregates review/analytics/recommendation data.
4. Admin can act on reviews or alerts.


8. Shopping/Customer Flow
-------------------------
Signup/login flow:

1. Customer opens auth drawer.
2. Customer registers or logs in.
3. OTP/password reset flows are available.
4. After login, customer can access account, cart, wishlist, orders, rewards,
   notifications and reviews.

Account/profile flow:

1. Customer opens /shopping/account.
2. Profile is loaded from /api/v1/user/me.
3. Customer can update profile data and address information.
4. PhoneCompletionBanner encourages missing phone completion.

Cart/wishlist flow:

1. Customer adds product to cart or wishlist.
2. Backend stores cart and wishlist in User model.
3. Cart slice fetches and updates state.
4. Wishlist page can move products to cart or remove them.

Review flow:

1. Customer opens product reviews or my reviews.
2. Customer submits review with rating, title, content and optional images.
3. Backend validates purchase/review rules.
4. Product rating stats update.
5. Admin moderation can manage review visibility.

Notification flow:

1. Notification is created by order/payment/admin/drop/offer logic.
2. SocketBridge receives notification refresh events.
3. NotificationsDropdown and NotificationsPage show unread/read items.
4. User can mark notifications as read.
