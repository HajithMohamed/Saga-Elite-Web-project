PERSON 1 DOCUMENTATION
Role: System Architecture, Landing Page and Promotion System Developer


1. Role Summary
---------------
This role is responsible for the foundation and public-facing promotional
experience of Saga Elite. The work includes project architecture, backend API
registration, global middleware setup, landing page data loading, hero/banner
systems, promotional drops, surprise gift logic, site configuration, public
content pages and third-party authentication integrations.

The role connects the brand experience to the backend. It makes sure the public
homepage, hero section, banners, limited-edition promotion blocks, mystery gift
section, contact/newsletter systems and editable site configuration are powered
by real APIs and database collections.

4. Database and Model Responsibilities
--------------------------------------
Primary models:

- Banner
  Stores landing/promotion banners with title, image, CTA, active window,
  display order and active status.

- Gift
  Stores mystery collectibles. Key fields: name, drop, isActive, probability,
  condition, minOrderValue, rarity, description, internalNotes and imageUrl.

- Image
  Stores Cloudinary image metadata for Product, Drop, Review, User and System
  images. Used for hero, ad, logo and category-logo media.

- SiteConfig
  Key-value store for editable site content, branding, SEO, maintenance,
  policies, contact content and payment details.

- Category
  Category tree with name, slug, parentCategory, ancestors and display fields.

- Banner
  Active promotional banner collection used by landing APIs.

- Deal
  Active deal records connected to promotional product display.

- ContactInquiry
  Stores customer contact form submissions with status and response metadata.

- NewsletterSubscriber
  Stores newsletter email subscribers.

- Influencer
  Stores influencer or community collaborator records.

- AdminLog
  Stores admin audit actions generated by admin-log-middleware.

- User
  Shared with Person 4 for Google/Facebook account integration.


5. Middleware Used By This Role
-------------------------------
- helmet, compression, cookieParser, express.json and configureCors in server.js
  Global server protection, compression, cookies, JSON body parsing and CORS.

- guest-tracking-middleware.js
  Assigns a guestToken cookie for public sessions.

- rateLimitinMiddleware.js
  Applies authLimiter, generalLimiter and contactLimiter.

- customMiddleware.js
  Logs request method, URL, IP, user agent, status and duration.

- maintenance-mode.js
  Blocks public traffic if the maintenance SiteConfig key is enabled.

- optional-auth-middleware.js
  Allows public product/drop/landing requests to optionally include user data.

- auth-middleware.js
  Protects admin-only content management APIs.

- admin-middleware.js
  Protects admin pages and endpoints with requireAdmin, requireSuperAdmin and
  requirePermission.

- request-validation.js
  Used for validateBannerCreate, validateBannerUpdate, validateDropCreate,
  validateDropUpdate, validateImageUploadRequest, validateImageReorder,
  validateDeleteAllImages, validateNewsletterSubscribe, validateContactSubmission,
  validateContactUpdate, validateGoogleAuth and validateFacebookAuth.

- multer-middleware.js
  Used for image upload and receipt image/PDF upload support.

- admin-log-middleware.js
  Records successful admin changes to banners, images, gifts, site config and
  related resources.


6. Main Business Logic
----------------------
Landing page data logic:

1. Home.jsx calls getLandingData() from landing-api.js.
2. landing-api.js performs parallel API calls for products, deals, category
   logo images, ad images, offers, active drops, active banners and hero images.
3. If active banners exist, the hero uses banner data.
4. If no banners exist, the hero falls back to system hero images.
5. Active drops can override hero slides and announcement sections.
6. Offers and deals are mapped into promotional product cards.
7. The page remains usable even if one API call fails.

Banner logic:

1. Admin creates banner with image, title, CTA and active window.
2. Backend filters active banners by isActive and active date range.
3. Frontend normalizes the banner payload into carousel slides.
4. Display order controls ordering.

Gift/mystery collectible logic:

1. Admin creates gifts in GiftManager.
2. Gift can be global or attached to a drop.
3. Gift can be always available, min order value based or per drop.
4. Order controller selects eligible gifts using weighted probability.
5. Gift is attached to the order but hidden until confirmation/reveal logic.
6. Gift analytics shows how many orders received gifts.

Site configuration logic:

1. Admin saves site config values by key.
2. SiteConfig stores flexible Mixed values.
3. Public pages use useShopAbout or direct site-config calls.
4. Maintenance mode also reads from SiteConfig.

OAuth integration logic:

1. Frontend sends Google/Facebook access token.
2. Backend verifies token or fetches social profile.
3. Existing user is found by provider ID or email.
4. New user is created if needed.
5. create-send-token utility issues JWT and cookie response.


7. Admin Panel Flow
-------------------
Admin image/banner/content flow:

1. Admin logs in.
2. Admin opens Home Images, About Site Config, SEO Settings, Footer Manager,
   Policies Manager, Announcement Bar or Gift Manager.
3. PermissionGuard checks route access.
4. Backend checks authMiddleware and admin permissions.
5. Request is validated.
6. Controller updates Image, Banner, SiteConfig, Gift or related model.
7. admin-log-middleware records the action.
8. Public page uses the updated content on refresh.

Gift manager flow:

1. Admin creates gift with rarity and condition.
2. Admin can attach gift to a drop or keep it global.
3. Admin can edit or deactivate a gift.
4. Analytics counts attached and revealed gifts.
5. Order system uses active gifts during checkout/order confirmation.

Contact/newsletter flow:

1. Customer submits contact form or newsletter email.
2. Backend validates and stores the record.
3. Admin views inquiries or subscribers.
4. Admin can update inquiry status.


8. Shopping/Public Flow
-----------------------
1. Customer visits the homepage.
2. Public layout renders MainHeader, Home and MainFooter.
3. Guest tracking middleware creates a guest token.
4. Home page loads hero, banners, live drop, products, offers and gift sections.
5. Customer can open drops, product listing, offers, about, contact or legal
   pages.
6. Customer sees active promotional content and drop countdowns.
7. Customer can subscribe to newsletter or send a contact inquiry.
8. Customer later receives gift eligibility through the checkout/order system.
